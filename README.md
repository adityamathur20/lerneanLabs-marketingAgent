# lerneanLabs-marketingAgent

This repo holds the code for marketing and lead Agent — an n8n workflow export
(`Complex Automations.json`) that bundles **10 independent, production-style
marketing/agency-operations automations** onto a single canvas.

This README documents the workflow in depth: what each automation does, what
triggers it, where its data comes from, what it calls out to, what it
produces, and what is missing or risky about the current implementation.

---

## ⚠️ Security note — read this first

Scanning the workflow JSON turned up **live credentials committed in plain
text**:

- Two Google Gemini API keys hardcoded directly in `httpRequest` node URLs
  (nodes `Gemini Vision API1` and `Gemini Generate SMS`, inside the *Invoice
  Digest* and *AI First Outreach* sections).
- A **Supabase `service_role` JWT** (the key that bypasses Row Level Security
  entirely) hardcoded in plain text in four places (`Query New Leads`,
  `POST → compliance-gate`, `Update Lead Stage` — all in the *AI First
  Outreach* section), pointing at a specific live Supabase project.

Everything else in the workflow correctly uses n8n's stored **credentials**
(Google OAuth2, a generic `httpQueryAuth` credential for Gemini, an OpenAI
credential) — only these five nodes bypass that and inline the secret.
Since this repository is now public, treat those two API keys and that
Supabase key as **compromised**:

1. Rotate/regenerate the Gemini API key(s) in Google AI Studio / Cloud
   Console.
2. Rotate the Supabase `service_role` key for that project (Project
   Settings → API), and audit the `leads` table / `compliance-gate` edge
   function for unexpected access in the meantime.
3. Replace the inline values in those 5 nodes with the same
   `httpQueryAuth` / header-auth **credential** pattern already used
   everywhere else in this workflow.
4. Consider scrubbing git history, not just the current file — the keys
   remain recoverable from old commits even after being removed from HEAD.

This is not addressed further below except where relevant to a specific
automation's data flow — the actual key values are intentionally **not**
reproduced anywhere in this README.

## What this file actually is

- **Format:** n8n workflow export, `active: true`, execution order `v1`.
- **Scale:** 188 nodes total → 178 executable nodes + 10 sticky notes (used
  purely as section headers/titles on the canvas).
- **Structure:** Verified via the workflow's connection graph (BFS from
  every trigger node) that the 10 sections are **fully independent** — zero
  shared nodes, zero cross-triggering between sections. This is a bundle of
  10 separate automations living in one file, not a single orchestrated
  pipeline.
- **Node type mix:** 67 Code (JavaScript) nodes, 28 Google Sheets, 24 HTTP
  Request, 21 Gmail, 8 Google Drive, 8 native OpenAI, 6 Schedule Trigger, 8
  Form Trigger, 2 Merge, 2 If, 1 Split Out, 1 Google Drive Trigger, 1 Google
  Docs.
- **No MCP servers are used anywhere in this workflow.** There is no
  `mcpTrigger` node, no `@n8n/n8n-nodes-langchain.mcp*` node, and no
  LangChain "AI Agent" node with attached tools. This is a classic
  node-by-node / raw-HTTP automation stack, not an MCP-orchestrated agent.
  All "AI" calls are either (a) direct `HTTP Request` nodes hitting Google's
  Gemini REST API, or (b) native n8n `OpenAI` (chat) nodes.

## The 10 automations

Each section below covers: **Trigger (input)** → **Data sources read** →
**AI/external calls** → **Output** → **Notes/gaps**.

### 1. AI D2C Launch Kit PRO — Multi-Agent Production Engine
- **Trigger:** Form — "🚀 AI D2C Launch Kit PRO" (product name, category,
  description, price, target audience, etc.)
- **Flow:** A 4-agent pipeline over Gemini (`gemini-2.5-flash-lite` /
  `gemini-2.5-flash-image`):
  1. **Agent 1 – Market Intelligence** (positioning/competitor angle)
  2. **Agent 2 – Senior Copywriter** (60+ marketing assets: ad copy, product
     descriptions, email variants, social captions, etc.)
  3. **Agent 3 – Gemini 2.5 Image Gen** (`gemini-2.5-flash-image`,
     i.e. "nano-banana") generates hero/campaign images per prompt, split
     out and generated per-image, extracted from base64 to binary
  4. **Agent 4 – QA Reviewer** scores the whole kit and returns a
     pass/fail-style verdict
  - Generated images are uploaded into an auto-created Google Drive
    campaign folder (`🚀 {brand} — {product} — {campaignId}`).
- **Data sources:** Only the form submission; no external product/market
  data feed — market intelligence is generated by the LLM from the form
  inputs, not looked up.
- **Output:** Row appended to a "D2C Products" Google Sheet (audit log);
  one rich HTML email to the **agency** (`agentEmail` from the form) with
  the full asset kit + embedded image previews; one executive-brief email
  to the **brand owner** (`ownerEmail`).
- **Notes:** Recipient emails are correctly dynamic (`$json.agentEmail` /
  `$json.ownerEmail`). No dedupe — resubmitting the form regenerates a full
  new kit with a fresh campaign ID.

### 2. AI Real Estate Marketing Kit — Full System
- **Trigger:** Form — "🏠 AI Real Estate Marketing Kit" (property title,
  type, transaction type, price, location, etc.)
- **Flow:** Gemini (`gemini-2.5-flash`) generates a full marketing kit
  (portal description, social posts, broker pitch, neighbourhood guide,
  open-house invite, follow-up emails) plus a separate image-prompt step
  feeding `gemini-2.5-flash-image` twice — one Instagram visual, one
  LinkedIn visual.
- **Data sources:** Only the form submission.
- **Output:** Row appended to a "Real Estate Listings" Google Sheet; HTML
  marketing-kit email + visuals email to the agent (`agentEmail`); a
  separate report email to the property owner (`ownerEmail`).
- **Notes:** Clean, fully dynamic recipient handling. No live MLS/portal
  data pull — content is generated purely from form text.

### 3. AI Client Onboarding
- **Triggers (3):**
  - Form — "🏥 New Client Onboarding" (client name/company/email, service
    requested)
  - Schedule — daily 10 AM ("Kickoff Follow-Up?")
  - Schedule — every Monday ("Weekly Check-In")
- **Flow (form path):** Looks up the requested service in a "Services"
  Google Sheet (SOPs/deliverables/timeline per service type), merges with
  client form data, asks Gemini (`gemini-2.5-flash`) to build a full
  project plan + deliverable timeline from those SOPs, expands deliverables
  into individual tracker rows.
- **Flow (follow-up paths):** The two schedule triggers read the client
  roster sheet, filter for clients 2+ days since welcome / calculate
  week-number for active clients, and use Gemini (`gemini-2.0-flash`) to
  draft a follow-up reminder or a weekly check-in email per client.
- **Data sources:** A Google Sheets "Services"/SOP database is the source
  of truth for what gets delivered and when — this is the one automation
  that reads pre-existing structured agency data rather than generating
  everything from scratch.
- **Output:** Rows to "Summary" / "Client_Projects_Tab" / "Communications"
  sheets; a welcome email + internal copy on new onboarding; automated
  reminder/check-in emails on schedule.
- **Notable gap:** The scheduled reminder/check-in emails correctly go to
  `$json['Client Email']`, but the **initial welcome email and its internal
  copy are both hardcoded to `admin@reoclaw.com`** instead of the client's
  actual email — as configured, the very first onboarding email never
  reaches the client.

### 4. AI Lead Gen Machine — Reply-Aware
- **Triggers (3):** Form — "🚀 Launch Lead Gen Campaign" (agency name,
  service sold, UVP, sender identity); Schedule — daily 10 AM (Email 2 due);
  Schedule — daily 11 AM (Email 3 due).
- **Flow:** Reads a contacts list from a Google Sheet named
  `apollo-contacts-export` (i.e., a **manually exported CSV from Apollo.io,
  imported into Sheets** — there is no live Apollo API call anywhere in this
  workflow despite the naming). Merges each contact with the campaign
  context, personalizes Email 1 per-contact via OpenAI (`gpt-4o-mini`),
  sends it, and logs the Gmail `threadId`. Two scheduled "gate" checks
  later fetch that Gmail thread and treat **message count ≥ 2 as "replied"**
  to decide whether to send Email 2 (3+ days later) / Email 3 (4+ days
  later, a "breakup" email) or stop the sequence.
- **Data sources:** Apollo contacts sheet (must be populated manually
  beforehand) + a "Campaign CRM" sheet used as sequence-state tracker.
- **Output:** Rows in the Campaign CRM sheet tracking stage/reply status;
  up to 3 sequential outreach emails per contact.
- **Notable gap:** All three outreach emails (`Send Email 1/2/3`) are
  **hardcoded to `teamlancemart@gmail.com`** rather than the contact's real
  email address. As configured, this automation does not actually deliver
  cold outreach to leads — everything routes to one fixed inbox (looks like
  a safety/demo default that was never wired to the real per-contact
  address). Reply detection via raw thread message-count is also fragile —
  it can't distinguish a genuine reply from a bounce, auto-responder, or CC.

### 5. AI Influencer Factory — Content Engine
- **Trigger:** Form — "🤖 AI Influencer Factory" (name, handle, niche,
  gender, etc. for a *virtual* influencer persona)
- **Flow:** OpenAI (`gpt-4o-mini`) generates a character sheet, then a
  30-day content calendar in two halves (days 1–15, 16–30, merged), then a
  batch of carousel scripts + brand-pitch email drafts.
- **Data sources:** Only the form submission.
- **Output:** Rows to a "Master" tab (one row summary) and a "Calendar" tab
  (expanded to one row per day) in an "AI Influencer Factory" Google Sheet;
  a single mega-email with everything (character sheet, calendar, prompts,
  pitches) sent to `$json.email`.
- **Notes:** No image generation in this section (calendar entries include
  "Ideogram prompts" as text per the form description, but nothing here
  actually calls an image-gen API for it) — the visuals are meant to be
  generated downstream by the user using the produced prompts.

### 6. AI Festival Campaign Generator PRO
- **Trigger:** Form — "🎁 AI Festival Campaign Generator" (festival
  selection from a large dropdown — Diwali, Holi, Christmas, Eid, etc. —
  plus product/brand details)
- **Flow:** Same 4-agent pattern as the D2C kit, festival-flavored:
  Agent 1 (Festival Intelligence) → Agent 2 (Festival Copywriter, 50+
  assets) → three separate Gemini image-gen calls (festival visual, story
  visual, ad banner) → Agent 4 (Campaign QA Reviewer). All three generated
  images are uploaded to an auto-created Drive folder and the flow waits
  (Merge node, 3 inputs) for all three uploads before continuing.
- **Data sources:** Only the form submission.
- **Output:** Row in a "Festival_Campaigns" Google Sheet; campaign-kit email
  to the agent; campaign-brief email to the owner, both dynamically
  addressed.
- **Notes:** Cleanest/most complete of the image-generating pipelines
  (proper wait-for-all-uploads synchronization before emailing).

### 7. Invoice Digest — Daily Email Report
- **Triggers (2):** Google Drive Trigger — polls an "Invoices" folder
  hourly for new files; Schedule — daily 8 AM digest.
- **Flow (ingest path):** On a new file, downloads the PDF, base64-encodes
  it, and sends it to Gemini (`gemini-2.5-flash`, vision/multimodal) with a
  strict prompt: extract `total_amount`, `currency`, whether a genuine
  handwritten/stamped signature is present and valid, and populate an
  `errors[]` array for anything wrong (no signature, missing total, not a
  valid invoice). An `If` node routes to a "Flagged Invoices" sheet
  (+ moves the file to a "Flagged" Drive folder) or a "Verified" sheet.
- **Flow (digest path):** Once daily, reads both sheets, aggregates stats
  (verified vs flagged counts, currency totals), and emails an HTML summary
  to the internal team inbox.
- **Data sources:** Whatever PDFs land in the watched Drive folder.
- **Output:** Verified/Flagged sheet rows, sorted Drive folders, one daily
  summary email.
- **Notes:** This is the section with one of the hardcoded Gemini API keys
  (see security note above). No OCR fallback if Gemini's JSON response
  fails to parse — falls back to an all-null/flagged result, which is
  reasonable defensive behavior.

### 8. AI First Outreach (compliance-gate routed)
- **Trigger:** Schedule — every 60 seconds (polling).
- **Flow:** Queries a **Supabase** Postgres REST endpoint
  (`/rest/v1/leads?stage=eq.new&phone=not.is.null`) for new leads with a
  phone number, generates a personalized first-touch SMS via Gemini
  (`gemini-2.5-flash`, kept under 130 characters), then POSTs the message to
  a Supabase **Edge Function** called `compliance-gate` with flags like
  `defer_if_outside_hours: true` and `ai_disclosure_required: true`. The
  code explicitly notes the model is *not* asked to add "Reply STOP" —
  the compliance-gate function appends that (and presumably enforces
  TCPA quiet-hours/opt-out rules) server-side. Finally it PATCHes the
  lead's `stage`/`next_action` back in Supabase based on whether the gate
  reported the message as sent.
- **Data sources:** A Supabase `leads` table (real estate lead DB), not
  visible in this repo — schema/tenant logic lives entirely in Supabase.
- **Output:** Lead stage updates in Supabase; the actual SMS **send**
  itself happens *inside* the external `compliance-gate` Edge Function,
  which is not part of this n8n workflow or this repository — this
  workflow only prepares the message and hands it off.
- **Notes:** This is the section with the hardcoded Supabase service-role
  key and the second hardcoded Gemini key (see security note). Because the
  actual SMS delivery logic lives in an opaque external function, this
  workflow cannot itself confirm delivery beyond whatever the gate's HTTP
  response reports.

### 9. AI Proposal & Invoice Autopilot
- **Trigger:** Form — "AI Proposal And Invoice" (client name, company,
  service type, goals/scope, budget, timeline, email, industry).
- **Flow:** OpenAI (`gpt-4o`) generates proposal + invoice content from the
  form data; two parallel branches label and then merge/combine a
  **Proposal PDF** and an **Invoice PDF** into one binary set; sends both as
  a combined email to the client; logs to a "Client CRM" sheet with
  status `Proposal Sent`. A `Wait 3 days` node then re-checks CRM status —
  if still `Proposal Sent` (no status change recorded), it sends one
  automatic follow-up email and updates the CRM.
- **Data sources:** Only the form submission.
- **Output:** Combined PDF email to the client; CRM sheet rows; one
  automated 3-day follow-up.
- **Notes:** The only automation in the bundle that produces and emails
  actual PDF documents. Follow-up logic is a single wait-and-check step
  (no further escalation beyond one follow-up).

### 10. AI Learning Machine — Autonomous Research Engine
- **Trigger:** Form — "🧠 AI Learning Machine" (topic, current knowledge
  level, specific questions, notification email).
- **Flow:** OpenAI (`gpt-4o-mini`) turns the request into search queries,
  which are used to call the **YouTube Data API v3** (`search`, top 10
  relevant medium-length videos). Video details are extracted, then OpenAI
  synthesizes a master learning document from the research. A new **Google
  Doc** is created and its content is written via a direct `documents:
  batchUpdate` REST call (not the native "insert text" Docs node action).
- **Data sources:** Live YouTube search results (the only automation in
  the bundle that pulls in live external web/video data rather than
  generating everything from the LLM alone).
- **Output:** A populated Google Doc (the "learning kit"); a row in a
  "Learning Tracker" sheet; a notification email once the doc is ready.
- **Notes:** No general web-search step despite the form's description
  promising research "across YouTube and the web" — only YouTube is
  actually queried; there's no NotebookLM integration either, despite the
  form description mentioning it.

## Inputs (how work enters the system)

- **8 Form Trigger webhooks** — one human-facing intake form per
  customer-facing automation (D2C launch, real estate listing, client
  onboarding, lead-gen campaign launch, influencer brief, festival
  campaign, proposal/invoice request, learning-topic request).
- **6 Schedule Triggers** — daily/weekly cron jobs driving follow-up
  sequences (client onboarding reminders/check-ins, lead-gen email 2/3),
  the invoice digest, and the 60-second outreach poller.
- **1 Google Drive Trigger** — polls a specific "Invoices" folder hourly
  for new files.
- No workflow in this file is triggered by an inbound webhook from a
  third-party system (e.g., no Stripe/Twilio/Apollo webhook, no chat
  platform trigger) — everything is either a form fill, a clock, or a
  Drive poll.

## Outputs (what the system produces)

- **Email** (Gmail) — HTML campaign kits, briefs, reminders, proposals,
  invoices, digests, notifications — 21 Gmail nodes across every automation.
- **Google Sheets rows** — used as the persistent "database"/CRM/audit log
  for nearly every automation (28 nodes: append/update/read).
- **Google Drive assets** — generated campaign images and organized
  invoice files (28 upload/folder/move/download operations across Drive
  nodes).
- **Google Docs** — one automation (Learning Machine) produces a full
  document as its deliverable.
- **Supabase writes** — lead-stage updates in the real-estate outreach
  automation.
- No workflow writes back to Apollo, Stripe, a real CRM (HubSpot/Salesforce),
  or any ads platform — despite several automations being framed as
  "campaign launch" tools, none of them push ads live anywhere; the output
  is always content + assets handed to a human via email/Sheets/Drive.

## Where the data actually comes from

- **User-submitted form fields** are the primary input for 8 of the 10
  automations — nearly all "intelligence" (market analysis, competitor
  angles, festival relevance, project plans) is **LLM-generated from those
  form fields**, not looked up from a real external data source.
- **Pre-populated Google Sheets** act as reference data in two cases: the
  Client Onboarding "Services" sheet (SOPs/deliverables per service) and
  the Lead-Gen "Apollo contacts" sheet (must be manually exported from
  Apollo.io and pasted in — there's no live Apollo API integration).
  Both Sheets act as internal data stores/CRMs afterward.
- **Live external data** is only pulled in two places: the YouTube Data
  API (Learning Machine) and whatever PDFs a human drops into the watched
  Drive folder (Invoice Digest). Everything else is synthetic content
  generated by an LLM from user-provided text.
- **Supabase** is the one automation with a real backing database (`leads`
  table) that's presumably populated by some other system not present in
  this repo.

## Capabilities summary

- Multi-agent LLM content pipelines (market intel → copy → image → QA)
  reused as a pattern across 2 of the 10 automations (D2C, Festival).
- AI image generation via Gemini 2.5 Flash Image ("nano-banana"),
  auto-organized into Drive campaign folders.
- Multi-touch, reply-aware email sequencing with a (fragile) reply-detection
  gate based on Gmail thread state.
- Scheduled recurring operations: weekly/daily client touchpoints, daily
  invoice digest, 60-second lead-outreach polling.
- Document intelligence: Gemini-vision invoice parsing with signature/amount
  validation and a flagged/verified triage workflow.
- PDF generation and delivery (proposal + invoice) with a follow-up
  cadence gated on CRM status.
- A TCPA-aware SMS compliance handoff pattern (build message in n8n →
  delegate compliance + delivery to an external gated service).
- Autonomous research: form topic → generated search queries → YouTube
  data → synthesized Google Doc.

## Known gaps, risks, and things that are not actually working end-to-end

1. **Hardcoded secrets in a public repo** — 2 Gemini API keys + a Supabase
   `service_role` key. See the security section at the top; rotate these.
2. **Two automations don't actually reach real recipients as configured:**
   - Lead-Gen's three outreach emails are hardcoded to
     `teamlancemart@gmail.com` instead of each contact's real address.
   - Client Onboarding's welcome email + internal copy are hardcoded to
     `admin@reoclaw.com` instead of the new client's address.
   These look like leftover test/demo values that were never parameterized.
3. **"Apollo" integration is not an API integration** — it's a manually
   exported CSV pasted into a Google Sheet. There's no live Apollo.io API
   call, so the lead list never refreshes automatically.
4. **No true web search** for the Learning Machine despite the form
   promising research "across YouTube and the web" — only YouTube is
   queried; no NotebookLM hookup either, despite being mentioned in the UI copy.
5. **Fragile reply detection** — the Lead-Gen reply gate treats "Gmail
   thread has ≥2 messages" as "the lead replied," which can't distinguish
   a genuine reply from a bounce, an auto-responder, or a CC'd message.
6. **No deduplication / idempotency** anywhere — resubmitting any intake
   form (D2C, Real Estate, Festival, Influencer, Proposal) fully
   regenerates a new campaign/kit with a new ID; there's no check for
   "have I already processed this."
7. **Minimal error handling on AI calls** — most `httpRequest` nodes calling
   Gemini have no retry/backoff configuration and no fallback if Gemini
   returns a non-2xx or malformed response (a few `Code` nodes do
   try/catch the JSON-parsing step specifically, e.g. invoice parsing and
   SMS generation, but that's not blanket coverage — e.g. the multi-agent
   D2C/Festival pipelines don't have QA-agent-failure fallbacks).
8. **SMS delivery is opaque** — the actual sending of compliant SMS in
   "AI First Outreach" happens inside an external Supabase Edge Function
   not included in this repository, so this workflow can't be fully
   understood, tested, or audited standalone; you'd need the
   `compliance-gate` function source to see the full picture (quiet-hours
   logic, opt-out handling, actual SMS provider used).
9. **No MCP usage** — if the intent was to build these as MCP-callable
   tools/agents (e.g., for a chat-based agent to invoke), none of that
   exists yet; every automation is a fixed, linear n8n pipeline triggered
   by a form or a clock, not an agent with tool-choice.
10. **Multiple Google Sheets referenced by name only** (`doc=None` in
    several nodes, meaning the sheet is referenced by a raw ID/expression
    rather than a resolvable name) — those underlying spreadsheets are not
    included in this repo, so several automations can't be run standalone
    without first recreating the exact tab structure they expect
    (e.g. `Client_Onboarding_Clients_Tab`, `Onboarding Clients`,
    `Campaign_CRM_Tab_Template`, `Invoices Track`, `AI Influencer Factory`).
